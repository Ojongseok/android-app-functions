Tech Trend Briefing

Android App Functions

AI 시대에 맞춰 변화하는 "앱"
구글이 제시하는 AI 에이전트와 앱의 결합

데이터유니버스 서비스개발팀|모바일파트 오종석 사원
01 · INTRO

AI가 하루가 다르게 바뀌는 동안,
앱이라는 생태계도 함께 바뀌고 있습니다

검색, 글쓰기, 업무 처리까지 AI 에이전트가 대신 해주는 것이 익숙해지면서, 사용자가 "앱을 직접 여는 것"에서 "에이전트에게 시키는 것"으로 행동 방식이 이동하고 있습니다. 이 흐름에 대한 안드로이드 플랫폼의 답이 바로 App Functions입니다.

AI의 전면화

검색·업무·일상 전반에 AI 에이전트가 자연스럽게 자리잡는 중입니다.

사용자 행동의 이동

"앱 열기 → 탐색 → 실행" 대신 "요청하기(음성·텍스트) → 결과 받기"로 사용 경험이 짧아지고 있습니다.

플랫폼의 대응

안드로이드는 이 변화에 맞춰 앱이 에이전트와 대화할 수 있는 공식 창구를 마련했습니다.

02 · CONCEPT

App Functions란 무엇인가요?

한 줄로 정리하면, "앱마다 자기 자신의 MCP(Model Context Protocol)를 갖게 되는 것"입니다. 앱이 가진 기능을 AI 에이전트가 호출할 수 있는 '도구'로 등록해두면, 사용자를 대신해 에이전트가 그 기능을 직접 실행할 수 있게 됩니다.

04 · HOW IT WORKS

어떻게 동작하나요?

사용자의 요청 한마디 — 음성이든 채팅 프롬프트든 — 가 아래와 같은 흐름을 거쳐, 클라우드를 거치지 않고 내 기기 안에서 여러 앱의 기능으로 곧장 연결됩니다.

사용자 요청

음성 또는 채팅 프롬프트로 하고 싶은 일을 자연어로 전달

AI 에이전트

Gemini 등 온디바이스 에이전트가 요청을 해석

OS 기능 레지스트리

기기에 설치된 앱들의 함수 목록을 조회

해당 앱 실행

알맞은 App Function이 기기 내에서 바로 실행

클라우드 왕복 없음 → 빠른 응답
기기 밖으로 데이터 전송 없음 → 프라이버시 보호
05 · CURRENT STATUS

지금 당장 누구나 쓸 수 있나요?

아직은 아무 앱, 아무 사용자에게 열려있는 기능은 아닙니다. 현재는 다음과 같은 제한적인 범위에서만 동작합니다.

Android 16 이상
실험용 프리뷰(Experimental Preview)
Gemini 에이전트 비공개 테스트

신뢰 테스터 대상

현재는 선정된 일부 신뢰 테스터에게만 Gemini를 통해 비공개로 제공됩니다.

개인은 제한된 환경만

일반 개인 사용자는 조기 액세스 등록을 통해 제한된 환경에서만 체험 가능합니다.

API도 계속 변경 중

실험 단계이므로 API 형태와 지원 범위는 정식 출시 전까지 계속 바뀔 수 있습니다.

06 · WHAT CHANGES

그래서, 무엇이 달라지나요?

지금까지 특정 작업을 하려면 반드시 해당 앱을 직접 열고, 화면을 탐색해서 원하는 기능을 찾아야 했습니다. App Functions가 자리잡으면, 사용자는 에이전트에게 음성이든 텍스트든 요청 한마디만 건네면 되고 — 앱들은 뒤에서 서로 협력해 결과를 만들어냅니다.

AS-IS · 지금까지
  • 1필요한 기능이 있는 앱을 직접 찾아서 실행
  • 2앱 안의 화면들을 탐색하며 이동
  • 3입력·선택 등 조작을 사람이 직접 수행
  • 4앱마다 매번 이 과정을 반복
TO-BE · App Functions 이후
  • 1에이전트에게 원하는 결과를 자연어로 요청
  • 2에이전트가 알맞은 앱의 기능을 자동 선택
  • 3화면 이동 없이 기기 내에서 즉시 실행
  • 4필요하면 여러 앱의 기능이 함께 연결되어 동작
07 · EXAMPLE 1

더 이상 메시지를 보내려고 앱을 열지 않습니다

"OO한테 오늘 저녁 늦는다고 메시지 보내줘"사용자가 에이전트에게 건네는 한마디 (음성·텍스트 모두 가능)

AS-IS
  • 1카카오톡 앱 실행
  • 2대화방 목록에서 상대 찾기
  • 3메시지 입력창 터치 후 직접 타이핑
  • 4전송 버튼 누르기
TO-BE
  • 1에이전트에게 음성 또는 텍스트로 요청 한마디만 전달
  • 2카카오톡의 '메시지 전송' App Function이 자동 호출
  • 3앱을 열거나 화면을 보지 않아도 전송 완료
08 · EXAMPLE 2

음식을 주문하려고 앱을 열지 않습니다

"저번에 시켰던 그 집 파스타 다시 주문해줘"사용자가 에이전트에게 건네는 한마디 (음성·텍스트 모두 가능)

AS-IS
  • 1배달의민족 앱 실행
  • 2가게 검색 또는 주문 내역 탐색
  • 3메뉴·옵션 하나씩 다시 선택
  • 4결제 화면까지 이동해 결제
TO-BE
  • 1에이전트에게 음성 또는 텍스트로 원하는 주문을 전달
  • 2주문 관련 App Function이 이전 주문 정보를 활용해 자동 구성
  • 3사용자는 최종 확인만 하면 주문 완료
09 · EXAMPLE 3 · 사내 서비스라면

우리 서비스에 비유하면 이렇습니다

먼 이야기가 아닙니다. 우리 회사의 앱으로 바꿔서 생각해보면 이렇게 그려볼 수 있습니다.

기프티콘 사용하기

AS-IS — 휴대폰쿠폰지갑 앱을 실행 → 쿠폰함에서 원하는 기프티콘을 찾아 → 매장 직원에게 바코드 제시

TO-BE — "이 기프티콘 지금 매장에서 쓸게"라고 요청하면, 쿠폰지갑의 App Function이 바로 바코드를 화면에 띄워줍니다.

가족 위치 확인하기

AS-IS — 휴대폰가족보호 앱을 실행 → 지도 화면으로 이동 → 가족 구성원의 위치를 직접 확인

TO-BE — "우리 아이 지금 어디 있어?"라고 물으면, 가족보호의 위치 조회 App Function이 즉시 답해줍니다.

10 · EXAMPLE 4 · 여러 앱이 함께 일한다면

앱들이 뒤에서 서로 협력하는 워크플로우

"Lisa 이메일에서 국수 레시피 찾아서, 필요한 재료를 쇼핑 목록에 추가해줘"하나의 요청으로 두 개의 서로 다른 앱이 연결됩니다

이메일 앱

레시피가 담긴 메일 검색 App Function 실행

AI 에이전트

레시피에서 재료 목록을 추출하고 정리

쇼핑리스트 앱

재료 추가 App Function으로 목록에 자동 반영

사용자는 두 앱 중 어느 것도 직접 열지 않았습니다. 이것이 App Functions가 그리는 미래입니다 — 앱은 배경에서 협력하고, 사용자는 결과만 받습니다.

11 · WHY IT MATTERS

왜 지금, 우리가 이걸 알아야 할까요

아직 실제 서비스에 바로 적용하기는 어렵고, 테스트만 가능한 단계입니다. 하지만 앱/웹 제품을 주력으로 하는 우리 회사가 이 흐름을 지금부터 이해하고 있다면, 에이전트와 앱이 결합하는 시기가 왔을 때 시장을 빠르게 선점할 수 있습니다.

얼리무버 어드밴티지

경쟁사보다 먼저 트렌드를 이해하면, 정식 출시 시점에 준비된 상태로 대응할 수 있습니다.

기획 관점의 전환

"어떤 화면을 만들까"에서 "에이전트에게 어떤 기능을 노출할까"로 기획의 질문이 달라집니다.

마케팅 관점의 전환

사용자가 앱을 켜지 않고도 우리 서비스를 경험하는 방식을 미리 고민해볼 수 있습니다.

12 · WRAP-UP

정리하며

오늘 이야기한 핵심

① App Functions는 앱마다의 모바일 MCP이자, ② Gemini 등 에이전트가 기기 내에서 직접 호출하는 기능이며, ③ 현재는 실험용 프리뷰 단계로 제한된 대상에게만 열려 있고, ④ UX의 축이 "앱 열기"에서 "요청하기(음성·텍스트)"로 옮겨가고 있다는 점입니다.

함께 고민해볼 질문

"우리 서비스라면, 어떤 기능을 App Function으로 노출할 수 있을까요?" 지금부터 기획·마케팅·개발이 함께 이 질문을 던져볼수록, 에이전트-앱 결합 시대가 왔을 때 더 빠르게 움직일 수 있습니다.
