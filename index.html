Tech Trend Briefing

Android App Functions

AI 시대에 맞춰 변화하는 '앱' - 구글이 제시하는 AI 에이전트와 앱의 결합

데이터유니버스 서비스개발팀|모바일파트 오종석 사원
01 · INTRO

AI가 하루가 다르게 발전하면서, 우리의 업무방식과 일상생활을 조금씩 바꾸고 있습니다.

검색, 글쓰기, 개발, 업무 처리까지 AI 에이전트가 대신 해주는데 '앱'은 사람이 직접 사용해야 할까요?
안드로이드는 사용자가 "앱을 직접 여는 것"에서 "에이전트에게 시키는 것"으로
AI 에이전트와 앱을 결합하는App Functions를 공개했습니다.

AI의 전면화

검색·업무·일상 전반에 AI 에이전트가
자연스럽게 자리잡는 중입니다.

사용자 행동의 이동

"앱 열기 → 탐색 → 액션" 대신
"에이전트에게 요청하기(음성·텍스트) → 결과 확인"로 사용 경험이 짧아지고 있습니다.

안드로이드 플랫폼의 대응

안드로이드는 이 변화에 맞춰 앱이 에이전트와 상호작용할 수 있는 공식 API를 마련했습니다.

02 · CONCEPT

App Functions란 무엇인가요?

쉽게 말해, "앱마다 자기 자신의 MCP(Model Context Protocol)를 갖게 되는 것"입니다. 앱이 가진 기능을 AI 에이전트가 호출할 수 있는 '도구'로 등록해두면, 사용자를 대신해 AI 에이전트가 그 기능을 직접 실행할 수 있게 됩니다.

05 · WHAT CHANGES

그래서, 무엇이 달라지나요?

지금까지 스마트폰에서 특정 작업을 하려면 반드시 특정 앱을 직접 열고, 화면을 탐색해서 원하는 기능을 찾아야 했습니다.
App Functions를 도입하면, 사용자는 무엇을 하고 싶은지 에이전트에게 음성이나 채팅을 통해 요청만 건네면 되고, 앱들은 백그라운드에서 서로 상호작용해 결과를 만들어냅니다.

AS-IS · 지금까지
  • 1필요한 기능이 있는 앱을 직접 찾아서 실행
  • 2앱 안의 화면들을 탐색하며 이동
  • 3입력·선택 등 조작을 사람이 직접 수행
  • 4앱마다 매번 이 과정을 반복
TO-BE · App Functions 이후
  • 1에이전트에게 원하는 결과를 자연어로 요청
  • 2에이전트가 알맞은 앱의 기능을 자동 선택
  • 3화면 이동 없이 기기 내에서 즉시 실행
  • 4상황에 따라 여러 앱의 기능이 함께 연결되어 동작
06 · EXAMPLE 1

더 이상 누군가에게 카카오톡 메시지를 보내기 위해 카카오톡을 열지 않습니다.

"OO한테 오늘 저녁에 늦는다고 카톡 보내줘"사용자가 에이전트에게 건네는 한마디 (음성·텍스트 모두 가능)

AS-IS
  • 1카카오톡 앱 실행
  • 2대화방 목록에서 상대 찾기
  • 3메시지 입력창 터치 후 직접 타이핑
  • 4전송 버튼 누르기
TO-BE
  • 1에이전트에게 음성 또는 텍스트로 요청 한마디만 전달
  • 2카카오톡의 '메시지 전송' App Function이 자동 호출
  • 3앱을 열거나 화면을 보지 않아도 전송 완료
07 · EXAMPLE 2

음식을 주문하기 위해 배달의 민족을 실행하지 않습니다.

"저번에 시켰던 그 집 파스타 다시 주문해줘"사용자가 에이전트에게 건네는 한마디 (음성·텍스트 모두 가능)

AS-IS
  • 1배달의민족 앱 실행
  • 2가게 검색 또는 주문 내역 탐색
  • 3메뉴·옵션 하나씩 다시 선택
  • 4결제 화면까지 이동해 결제
TO-BE
  • 1에이전트에게 음성 또는 텍스트로 원하는 주문을 전달
  • 2주문 관련 App Function이 이전 주문 정보를 활용해 자동 구성
  • 3사용자는 최종 확인만 하면 주문 완료
08 · EXAMPLE 3 · 여러 앱이 함께 일한다면

앱들이 백그라운드에서 서로 상호작용

"엄마가 보낸 문자메시지에서 비빔국수 레시피 찾아서, 필요한 재료를 쿠팡 장바구니에 담아줘"하나의 요청으로 두 개의 서로 다른 앱이 연결됩니다

사용자

요청 전달

AI 에이전트

문자메시지 검색 요청

문자메시지 앱

레시피 결과 반환

AI 에이전트

재료 정리 후 쿠팡 요청

쿠팡 앱

장바구니 담기 완료

AI 에이전트

완료 결과 확인

사용자는 두 앱 중 어느 것도 직접 열지 않습니다. — 앱은 백그라운드에서 상호작용하고, 사용자는 결과만 확인합니다.

09 · EXAMPLE 4 · 사내 서비스라면

데이터유니버스 서비스에 비유할 수 있습니다.

자사에서 제공하고 있는 서비스에도 얼마든지 적용 가능하다고 생각합니다.

기프티콘 구매하기

AS-IS — 휴대폰쿠폰지갑 앱을 실행 → 원하는 브랜드와 상품을 찾아 → 결제 정보를 입력해 구매

TO-BE — "스타벅스 아메리카노 한 장 구매해줘"라고 요청하면, 쿠폰지갑의 App Function이 결제부터 발급까지 바로 처리합니다.

가족 위치 확인하기

AS-IS — 휴대폰가족보호 앱을 실행 → 지도 화면으로 이동 → 가족 구성원의 위치를 직접 확인

TO-BE — "우리 아이 지금 어디 있어?"라고 물으면, 가족보호의 위치 조회 App Function이 즉시 답해줍니다.

발렛 차량 호출하기

AS-IS — 1566-5382로 전화 → 오토콜 ARS 안내에 따라 호출할 차량번호를 직접 입력

TO-BE — "내 차 좀 불러줘"라고 요청하면, 오토콜의 차량 호출 App Function이 등록된 차량번호로 즉시 호출을 접수합니다.

마감 임박 이벤트 확인하기

AS-IS — 이벤트유 앱을 실행 → 진행 중인 이벤트 목록에서 마감일을 하나씩 직접 비교

TO-BE — "오늘 마감되는 이벤트들 알려줘"라고 요청하면, 이벤트유의 이벤트 조회 App Function이 마감 임박 이벤트만 정리해줍니다.

10 · CURRENT STATUS

지금 당장 누구나 쓸 수 있나요?

아직은 모든 앱, 모든 사용자에게 열려있는 기능은 아닙니다. 현재는 다음과 같은 제한적인 범위에서만 동작합니다.

Android OS 16 이상
실험용 프리뷰(Experimental Preview)
Gemini 에이전트 비공개 테스트

신뢰된 테스터 대상

현재는 선정된 일부 신뢰 테스터에게만 Gemini를 통해 비공개로 제공됩니다.

개인은 제한된 환경만

일반 개인 사용자는 액세스 등록을 통해
제한된 환경에서만 체험 가능합니다.

지속적인 API 업데이트

실험 단계이므로 API 형태와 지원 범위는
정식 출시 전까지 계속 바뀔 수 있습니다.

11 · WHY IT MATTERS

왜 지금, 우리가 이 기술을 알아야 할까요

현재는 실제 서비스에 즉시 적용하기보다는 기술 검증과 테스트가 필요한 단계입니다.
하지만 앱·웹 기반 제품을 제공하는 기업으로서 AI 에이전트와 애플리케이션의 결합이라는 변화의 방향을 미리 이해하고 준비한다면, 관련 기술이 본격적으로 확산되는 시점에 보다 빠르게 대응하며 시장을 선점할 수 있습니다.

기술 변화에 대한 선제적 대응

새로운 기술과 플랫폼의 변화를 미리 이해함으로써, 실제 서비스 적용이 가능해지는 시점에 필요한 기술적·제품적 준비를 보다 빠르게 진행할 수 있습니다.

제품 기획 관점의 확장

기존의 "어떤 화면과 사용자 경험을 제공할 것인가"에서 더 나아가, "우리 서비스의 어떤 기능을 에이전트가 활용할 수 있도록 제공할 것인가"까지 제품 기획의 범위를 확장할 수 있습니다.

새로운 사용자 접점에 대한 준비

사용자가 직접 앱을 실행하지 않더라도 에이전트를 통해 서비스의 기능과 가치를 경험할 수 있는 새로운 사용자 접점을 미리 검토할 수 있습니다.
